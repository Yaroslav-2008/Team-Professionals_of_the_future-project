## 4. Распределение обязанностей по работе с репозиторием

Распределение основано на матрице RACI из первой работы.

| Обязанность | R (исполнитель) | A (ответственный) |
|---|---|---|
| Создание и настройка репозитория | Руководитель разработки (Сероштанов Я.К.) | Руководитель разработки |
| Поддержание структуры папок и файлов | Все участники, каждый для своих разделов | Руководитель разработки |
| Написание отчётов по практическим работам | Все участники согласно своим ролям | Руководитель разработки |
| Коммиты с осмысленными сообщениями | Каждый участник за свои изменения | Руководитель разработки |
| Проверка Pull Request | Руководитель разработки или архитектор ПО (Смирнов Я.В.) | Руководитель разработки |
| Слияние веток (merge) | Руководитель разработки | Руководитель разработки |
| Резервное копирование и актуальность | Все участники | Руководитель разработки |

## 5. Практическая работа с Git

Каждый участник клонировал репозиторий, создал собственную ветку вида `role/<название_роли>`, внёс изменения в соответствии со своей ролью, сделал коммит, отправил ветку на GitHub и открыл Pull Request.

ДОБАВИТЬ: по каждому участнику, который выполнил эти шаги, указать название ветки и ссылку на его Pull Request.

## 8. Вывод

Система контроля версий помогает организовать командную работу: все материалы хранятся в одном месте, а история изменений показывает, кто и что менял. Ветки позволяют работать параллельно и не мешать друг другу, а Pull Request даёт возможность проверить изменения до попадания в основную ветку. Коммиты с осмысленными сообщениями фиксируют вклад каждого участника.
